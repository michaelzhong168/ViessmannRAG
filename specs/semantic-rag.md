# 菲斯曼说明书问答 · 需求规格总纲 v1.2

版本日期为 2026-11-24。开发顺序为 **R01 真实问答基线 → R02 自动化评测 → R03 按失败原因优化**。阶段内以小单元为交付和验收粒度。本文定义新路线的功能、接口与验收依据。

## 1. 目标与首期范围

用户给出设备型号后，可以用「怎么打开暖气」「怎么查看水压」等日常说法提问。系统依据适用说明书回答，提供可回查的 PDF 物理页和原文。缺少型号或故障现象时追问。证据不足时说明缺口。涉及危险操作时转人工。

首批真实资料为「按键式官方中文操作指南」物理页 1–48，适用型号为 `L1P20-A1JF` 和 `L1P24-A1JF`。以后按型号与来源核定结果扩充。首期交付 CLI 和本地索引，产品验收后再排期对外接口和部署。

```text
PDF → Document → 版面解析与型号核定 → TextNode → 百炼 Embedding → LlamaIndex 本地索引
问句 + 型号 → 风险与故障码路由 → 型号内检索 Node → 千问生成 → 引用 Node 对应的原页
按原页标注的题集 → 同一问答入口 → 比对证据、答案与引用 → 失败归因 → 单项实验
```

## 2. R01 · 真实资料问答基线

| 单元 | 前置 | 交付物 | 验收 |
| --- | --- | --- | --- |
| R01-01 加载源文档 | 已取得说明书 PDF | 每份 PDF 对应一个逻辑 `Document`，关联 PDF 版本、物理页和核定型号范围 | 抽查所登记的 PDF 版本和型号页段。变更 PDF 时能识别来源版本已变化。 |
| R01-02 按版面生成 Node | R01-01 | 从 PDF 页内的章节、段落、操作步骤和表格直接构建 `TextNode` | 只凭 Node 就能回到来源 Document、物理页和坐标，并逐字核对原文与单位。验证未核定页、型号冲突不入库，来源文档和跨页信息不会混串。 |
| R01-03 向量建库 | R01-02 | `index` 命令，逐 Node 向量化、持久化并发布本地索引 | 真实资料完成一次建库和重载，记录 Node 数量。验证建库失败保留上一份完整索引，Embedding 模型不匹配提示重建。 |
| R01-04 型号内检索 | R01-03 | 输入原始问句和型号，输出 LlamaIndex 排序后的 Node 与分数 | 构造其他型号得分更高的用例，验证先筛型号再取 Top K。记录「打开暖气」「查看水压」的证据命中与排名。 |
| R01-05 风险与故障码路由 | R01-02 | 风险判定、型号检查与由故障表格 Node 生成的精确查询表 | 危险、缺型号和错型号在生成前处理。明确故障码按型号精确匹配，查表引用属于同一索引版本的对应 Node。 |
| R01-06 生成、引用与 CLI | R01-04、R01-05 | `ask` 命令，千问基于 Node 生成，程序组装结构化引用 | 真问真答至少覆盖一条口语操作题和一条参数查询题，人工查原页。离线验证无有效引用时拒答、虚构页码无法进入引用、模型超时可单独识别。 |

**阶段门禁**：从 PDF 跑通「加载 → 分块 → 建库 → 提问 → 回查原页」。冒烟同时覆盖模糊故障、明确故障码、缺型号、错型号、无依据和危险请求。保存结果与已知失败作为 R02 的输入。

## 3. R02 · 自动化评测

| 单元 | 前置 | 交付物 | 验收 |
| --- | --- | --- | --- |
| R02-01 标注与分集 | R01-02 | JSONL 题集、标注说明和题集版本 | 每题有稳定 ID、型号、问句和预期行为。应答题有按原页定位的证据组与必要事实。澄清和拒答题有预期状态。同一意图的改写整组归入调试集或留出集。维护者按原页复核留出题。 |
| R02-02 评测执行与归因 | R01-06、R02-01 | `eval` 命令与逐题报告 | 用同一问答入口跑样本，保存召回 Node ID、排名、回答、状态、引用和耗时。验证同一题重分块后仍可用原页标注匹配新 Node。用合成例分别验证资料缺失、召回遗漏、应答策略错误、引用错误、事实遗漏和服务异常可识别。 |
| R02-03 汇总与基线冻结 | R02-02 | 一份可复跑的真实基线报告和对应的运行配置 | 报告给出样本量、证据覆盖率、引用检查通过率、必答事实通过率、应答行为准确率及耗时。记录 PDF 版本、分块配置、索引、题集、模型与检索配置。明示工程调试题和正式留出题的统计范围。 |

**阶段门禁**：同一份配置可重新运行，失败时能看到缺在资料、召回、生成、引用还是服务。正式产品通过率、题量与延迟目标由维护者在选定留出集后核定。危险转人工、型号隔离和结构化引用门禁逐项通过。

## 4. R03 · 由失败样本驱动优化

| 单元 | 前置 | 交付物 | 验收 |
| --- | --- | --- | --- |
| R03-01 复现与排序 | R02-03 | 待解决项列表，每项关联失败题和证据 | 对优先项重跑原问题，定位所需原文是否入库、在第几位召回、是否用于答案。按用户影响和出现频次排序。 |
| R03-02 单项实验 | R03-01 | 每次一个优化单元，附同题前后报告 | 保持其他变量一致。记录改善题、退化题、耗时和调用量。只有证据表明改动有效且硬门禁仍通过时，才纳入候选版本。 |
| R03-03 留出集验证与交付 | R03-02 | 候选版本报告和可回退的版本记录 | 使用已核定留出题复测，抽查引用确实支持结论、操作步骤完整。以已核定的产品目标和硬门禁决定是否交付。 |

R03-02 按实际失败选择实验。每个实验有独立验收边界。

| 失败原因 | 优先验证的改动 |
| --- | --- |
| 目标原文缺失、表格或图标信息抽取缺失 | 补资料、核定页段、修解析，再验证从 PDF 抽出的 Node 是否足以支持答案。 |
| 目标原文已入库但未进入候选 | 先验证分块、章节上下文或召回深度。仍有系统性遗漏时比较词法与语义混合召回。 |
| 目标证据进入候选但排名不佳 | 比较排序或重排效果，同时检查上下文长度和延迟。 |
| 目标证据齐全但回答有错漏 | 调整提示词或证据上下文，复查事实、步骤与引用。 |
| 服务超时或调用失败 | 按阶段测量和复现，评估请求规模、超时与重试。 |

## 5. 共享数据契约

LlamaIndex 用 `Document` 表示载入的来源资料，用 Node 表示拆分后的检索单元。本项目选用 `TextNode` 存储手册片段。Node 支持文本、元数据与来源关系，PDF 的物理页、坐标和适用型号由本项目的加载与分块过程写入。[LlamaIndex Document 与 Node 文档](https://developers.llamaindex.ai/python/framework/module_guides/loading/documents_and_nodes/)、[LlamaIndex Schema API](https://developers.llamaindex.ai/python/framework-api-reference/schema/)。

| 对象 | 字段与规则 |
| --- | --- |
| `Document` | 对应一份来源 PDF。记录 `doc_id`、文件版本（内容指纹）和来源标识，并关联经核定的型号页段。PDF 原件供人工回查。 |
| `TextNode` | 索引、召回、生成上下文与引用使用同一个 Node。使用 `node_id`、`text` 和 `SOURCE` 来源关系。项目元数据记录物理页 `page_no`、页内坐标 `bbox`、`section` 和 `model_codes`。显式型号与核定范围取交集。首版每个 Node 只落在一个物理页，尽量保留完整段落、操作步骤或表格行。 |
| 索引快照 | 记录 PDF 版本、分块配置、Embedding 模型和索引格式版本。同一来源版本和分块配置重建时，Node ID 可复现。改变分块后允许产生新 ID。发送给模型时只选用任务需要的章节与原文。 |
| 问答结果 | 含 `answer`、`citations` 和 `error_code`。引用包含 `node_id`、`doc_id`、`page_no`、`bbox` 和逐字引文。页码从 1 开始，坐标沿用 PDF 页坐标系。程序从实际召回或查表命中的 Node 回填引用。 |
| 评测锚点 | 使用 PDF 版本、物理页、原文片段，必要时用坐标区分同页重复片段。每次将锚点匹配到当前快照的 Node。每组是支持同一事实的可替代锚点，答对一题须覆盖全部事实组。 |

新路线的建库、检索、故障码查表和引用均以 Node 为证据来源，停止生成和读取旧 `data/eu.jsonl`，引用与评测移除对 `eu_id` 的依赖。PDF 底层版面解析能力可复用。

## 6. 开发与版本约定

- **评测边界**：事实短语匹配用于自动检查。忠实性与操作完整性由人工用原页复核。
- **环境与数据**：离线门禁使用合成夹具和外部模型替身。真实说明书片段只在核定范围和授权环境内调用模型。密钥、真实语料、生成索引、正式金标与评测原始报告留在本地。
- **单元交付**：每次确认一个小单元的输入和验收项，记录验证命令及结果，按仓库约定独立复核。存在依赖的单元在前置达到验收后接续。PR 以 `dev` 为目标，由维护者手动合并。
- **旧规格衔接**：CHANGE_REQUEST 涉及原总纲 §1、§2.7、§3、§4，以及 G04、G05、G06、G11、G12。旧十四关实现和交付记录可查 Git 历史。当前项目按本总纲从 PDF 直接生成 LlamaIndex Node。线上版本由维护者回填。
- **v1.2 变更**：取代 v1.1 的 EU 证据契约。R01 的前两单元分别验收来源 Document 和按版面生成的 Node，后续单元使用 Node 直接完成索引、检索、查表和引用。R02 改按 PDF 原页标注，支持比较不同分块策略。
